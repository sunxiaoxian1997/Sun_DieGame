# Design Pillars

## 1. Death creates value

A death should create a persistent tool, state change, information advantage, or route.

## 2. Rules are readable

Players should be able to infer interactions from consistent visual and physical behavior.

## 3. Levels ask different questions

A new level should not merely rearrange the same obstacle. It should alter what the player must consider: location, sequence, scarcity, preservation, transport, timing, or reversal.

## 4. Solutions may be systemic

Unexpected solutions should remain valid when they follow established rules and do not exploit a technical defect.

## 5. Scope before spectacle

The prototype prioritizes a stable, testable gameplay loop over content, art, polish, or feature count.
